1. Quick start

  1. Click Quizzes (top left), then + New. Everything saves automatically: the top bar says Saved ✓.
  2. + Add a question. Write the statement, set the class name students write, the starter code and your reference solution.
  3. Add tests: + Output test (input → expected output) or + Code test (Java that calls the student's methods).
  4. Click ▶ Check tests with reference solution. Everything should be green. Then Run tests on starter code: most should fail.
  5. Open the Host console, pick the quiz, Use this quiz, ▶ a question.

Tip: open the Example: getting started quiz and click Duplicate to start from something that works.

Class name & how student code is put together

  • The student's code, the given code and the hidden helpers are compiled together. public on top-level classes is removed, so students may write several classes in one answer.
  • If the student writes methods without a class around them, they are wrapped in a class with the question's class name.
  • main(String[] args), main() and non-static (Java 25) main all work.

4. Tests

A question has any number of tests of two kinds. While a question is open, submissions are only compiled. Tests run when the question closes, or when you click Compile & run tests on one submission.

Output tests

Runs main of the question's class with Input as System.in and compares what it prints with Expected output. Choose how strictly:

ComparePasses when…Example: expected 1 2 / 3
Same lines (default)Same lines in the same order. Spaces at line ends and empty lines at the end don't matter."1 2 \n3\n\n" ✓ · "1 2\n3" ✗
Exactly the sameCharacter for character (only \r\n vs \n is ignored)."1 2\n3\n" ✗ (extra newline)
Same words/numbersSame words in the same order; spaces and line breaks don't matter."1\n2 3" ✓
Same lines, any orderSame lines, any order. Spaces at the start/end of lines and empty lines don't matter. Duplicates count."3\n1 2" ✓
Only the numbersOnly the numbers are compared (in order, ±0.000001); all other text is ignored."Sum: 1, 2, total 3" ✓

Leave Expected output empty and click Fill empty expected outputs: your reference solution's output is copied in.

Code tests

A few lines of Java that call the student's code and check results with the test functions. They are the body of a method, so you can use variables, loops, the given code and the hidden helpers. java.util.* and java.util.function.* are imported, plus whatever the student and the given code import.

int[] a = {3, 1, 2};
check(Solution.max(a), 3);
check(Arrays.equals(a, new int[]{3, 1, 2}), "max must not change the array");

If a code test doesn't compile with a student's code (e.g. they named the method differently), only that test fails, with the compiler message.

Weight, hidden, time

NameWhat students see, e.g. "empty array", "negative numbers". Make it say what is tested.
WeightPartial points = weighted share of passed tests. Give hard tests (edge cases, big inputs) more weight.
Time (s)Seconds before the test counts as too slow (endless loop or not efficient enough). Use it to test efficiency with a big input.
HiddenStudents only see that it failed, not the input or the expected output.

Every test runs separately: fresh static fields, its own input/output, a 512 MB stack. A System.exit, a crash or an endless loop only fails that one test.

5. Test functions (for code tests)

Every code test can call these directly. They come from runner/CQ.java. A failing check stops the test and shows its message to the student.

check(actual, expected)

Passes if the two values are equal. The message is expected …, got ….

  • Numbers by value: int, long, short, byte compare exactly, so check(sumLong(), 4000000000L) and check(count(), 3) both work. Doubles have a tiny tolerance (relative 1e-9).
  • Arrays and lists element by element, also nested (int[][]) and mixed (an ArrayList against an array).
  • Strings and chars exactly. "a" is not 'a'.
  • Everything else with equals. For your own classes without equals this compares references; check fields instead: check(r.name, "R3").
check(Solution.isPrime(7), true);
check(Solution.reverse("abc"), "cba");
check(Solution.sorted(new int[]{3, 1, 2}), new int[]{1, 2, 3});
check(Solution.digits(120), List.of(1, 2, 0));

check(double actual, double expected, double tolerance)

For doubles where you decide how close is close enough.

check(Solution.average(new int[]{1, 2}), 1.5, 1e-9);
check(Solution.sqrt(2), 1.41421356, 1e-6);

check(boolean condition) · check(boolean condition, String message)

Passes if the condition is true. Always give a message students understand: without one they only see "check failed".

int[] a = {5, 1, 4};
Solution.sort(a);
check(a[0] <= a[1] && a[1] <= a[2], "the array is not sorted: " + Arrays.toString(a));

fail(String message)

Fails the test right away with your message. For conditions that don't fit in one check.

Room[] r = Lab.build(new int[]{1, 2}, new int[][]{{1}, {}});
for (Room x : r) {
    if (x.doorsTo == null) fail("doorsTo of " + x.name + " was set to null");
}

output(() -> …) · output(String input, () -> …)

Runs the code and returns what it printed as a String, without comparing anything. The second form gives the code its own System.in, e.g. to call main with input.

String printed = output(() -> Solution.printTable(3));
check(printed.contains("9"), "3 x 3 = 9 is missing");

String out = output("3 4\n", () -> Solution.main(new String[0]));
check(out.strip(), "7");

checkOutput(() -> …, String expected)

Runs the code and checks the printed lines, in order. Spaces at line ends and empty lines at the end don't matter; spaces at the start of a line do.

checkOutput(() -> Solution.countdown(3), "3\n2\n1\nGo!");

checkOutputAnyOrder(() -> …, String expected)

Same lines, but in any order. Use it when the order depends on the student's approach, e.g. printing all paths or all exits of a labyrinth.

  • Spaces at the start/end of a line and double spaces don't matter; empty lines are ignored.
  • The order inside a line still matters: R3 R1 R0 is not R0 R1 R3.
  • Duplicates count: printing a path twice fails. Missing or extra lines fail too.
Room[] r = Lab.build(new int[]{1, 2, 2, 9, 5}, new int[][]{{1, 2, 4}, {3}, {3}, {}, {}});
checkOutputAnyOrder(() -> Labyrinth.printPaths(r[0]), "R0 R1 R3\nR0 R2 R3\nR0 R4");

lines(String text)

Splits text into a List<String> of lines (spaces at line ends and empty lines at the end removed). Handy with output for your own checks.

List<String> l = lines(output(() -> Solution.printAll(5)));
check(l.size(), 5);
check(l.get(0), "1");
Common pitfall: inside () -> … you can only use variables that are not changed afterwards (Java's "effectively final" rule). Make a new variable if needed.

6. Checking your tests

▶ Check tests with reference solutionRuns every test on your solution. All should pass; each test card turns green or red and shows why.
Fill empty expected outputsCopies your solution's output into output tests whose expected output is empty.
Run tests on starter codeMost tests should fail here; if one passes, it doesn't test much.
Use the reference solution's output as expectedAppears on an output test when your solution prints something different from the expected output.

Good habit: also paste a typical wrong answer (off-by-one, int instead of long) as the reference solution for a moment and check that some test catches it.

7. Full example

Class name: Solution. Statement:

Write a method that returns the **largest** value of an array.

- The array has at least one element.
- Values can be negative.

```
public static int max(int[] a)
```

Tests:

NameKindWeightCode
examplecode1check(Solution.max(new int[]{1, 5, 3}), 5);
one elementcode1check(Solution.max(new int[]{7}), 7);
all negativecode2check(Solution.max(new int[]{-4, -2, -9}), -2);
max at the end (hidden)code2check(Solution.max(new int[]{1, 2, 3, 4}), 4);

"all negative" catches students who start with int max = 0;, "max at the end" catches loops that stop one too early.

8. Running a session

  1. Start the server (start.bat). It prints the address for students (same Wi-Fi).
  2. Host console: pick the quiz, Use this quiz. Put /board on the projector.
  3. ▶ a question. When the time is up or you click Close now, the tests run on every submission.
  4. Grade: buttons, or keys 1 correct, 2 by tests, 0 wrong, J/K next/previous. Or Grade all by tests.
  5. Fixed a test during the session? Reload changes takes the newest version from the editor without losing players or points.

10. Sharing quizzes with other TAs

  • Each quiz is one file in quizzes/: text, images, tests and solutions.
  • ⬇ Export file downloads it; the other TA uses Import → From a file (or drops it on the editor).
  • 🔗 Share link: same Wi-Fi, works for 30 minutes; paste it under Import on the other laptop.
  • If the quiz already exists there, they choose: replace (the old one is kept as a backup) or keep both.
  • Older versions… restores autosaved versions; deleted quizzes are under Recently deleted.
Exported files and share links contain the reference solutions. Don't give them to students.
